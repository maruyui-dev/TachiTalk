# 2026-10-25 v2.0.0 r4：安装成功后自动清理

版本保持 **2.0.0 正式版**，以 `setup-r4` 区分旧包。只实现用户本轮明确授权的自动清理；未实施此前讨论的三部分资源重分包、ASR解耦、训练执行或模型导入。没有改下载选源/续传规则、云端、签名公钥、GPT-SoVITS、PyTorch或CUDA。

## 问题与行为

r3 安装成功后只清除 pending，仍保留下载分卷、合并ZIP、stage及backup。桌面旧安装实测30.52 GiB中，约20.95 GiB属于下载材料和解压暂存；此前仅按用户单独授权移出，不能当作产品已有自动清理。

r4 的正式链路：**验签与校验 → 解压/逐文件校验 → 备份/替换 → 持久提交事务 → 自动清理 → 自动启动主程序**。

- 清理本次已提交事务的 stage 和无需恢复的普通 backup。
- 清理本次签名归档对应缓存目录内的分卷、续传侧文件、合并ZIP和该任务的缓存元数据。
- 保留安装后的实际程序和语音环境、个人设置、对话记忆、角色、源音频、用户模型及其他下载任务。缓存目录中额外的用户文件也保留。
- 用户选择的外部离线ZIP不属于内部下载缓存，不自动删除。
- 用户改写了默认角色权重或默认参考音频，且备份哈希不匹配原托管清单时，保留该文件的备份；只清理可确认的普通安装材料。
- 每次启动5秒后，后台回收更早创建的临时更新器副本。只处理本程序管理目录中的UUID文件名，跳过本次启动后的新交接副本；运行中的EXE受Windows占用保护，不强杀。
- 日志、安装结果、进度记录和组件版本清单保留，用于状态检测和失败诊断。

本次没有更改分卷合并方式。安装过程中仍需临时空间，缩减的是**成功安装后的长期占用**；没有宣称降低了安装峰值空间或重新测得完整语音包安装时间。

## 提交、恢复与路径边界

新增 `app/updates/cleanup.py`。在完整 journal 持久提交后、移除 pending 前，写入本事务的 `cleanup.json`。记录很小；如有需保留的用户改动，只在提交时记录一次对应路径，不逐文件重写巨大JSON。

清理在更新器工作线程中、持有原安装锁时执行；主线程继续响应Qt事件。进度窗口新增“清理安装材料”，先枚举材料，随后显示实际清理文件数、总数、当前文件和更新时间。

- 清理中进程退出：小型任务记录仍在；下次启动自动交给独立更新器继续，不回滚已经提交的文件。
- 正常清理失败：安装结果仍 `ok=true`，独立记录 `cleanup.complete=false`、错误及剩余目录；窗口显示“安装成功，部分材料清理未完成”，资源页也提示日志位置。
- 已明确报告的清理失败标记为 blocked，避免自动恢复/重启循环。下次安装或恢复入口可再次尝试。
- 安装失败、回滚失败或仍有 pending 时，不清理这些修复材料。
- 只处理带有本版本提交标记的精确事务目录，及 `user_data` / `_qt_runtime_tmp` 下与签名归档SHA对应的下载任务；拦截路径越界、链接和目录联接。
- 不猜测删除无完成标记的历史事务、不扫描源音频/用户模型目录、不扫描整个缓存或整个work，也不处理此前可恢复移出的 `desktop-cleanup-20261025`。

## 修改范围

- 新增 `app/updates/cleanup.py`：清理记录、精确材料枚举和删除、清理重试检测、旧更新器副本回收。
- `app/updates/install.py`：持久提交与恢复时登记清理任务；识别需保留的默认模型/参考音频改动。
- `scripts/update_entry.py`：成功后在原安装锁内清理，记录安装与清理的独立结果，然后重启。
- `app/bootstrap.py`：中断清理交给独立恢复入口；延迟清理旧更新器副本。
- `app/updates/progress_window.py`、`app/ui/update_controls.py`：清理阶段及部分清理失败的真实状态。
- 新增 `tests/test_cleanup_lifecycle.py`、`tests/test_cleanup_guards.py`，更新实施状态和本文档。

修改前仅保存涉及文件的小型快照到 `work/auto-cleanup-20261025/before`；原脏工作区和HEAD未重置、未提交、未推送。

## 实际验证

复现阶段6项：3个保护场景通过，3个成功清理场景失败（共8处材料仍存在的断言）。实现后，35项相关测试 **10.142秒通过**，另新增启动继续清理测试1项 **0.541秒通过**。未重跑全量回归。

关键验证包括：

- 成功后清除内部下载材料、stage、普通backup；实际安装文件与个人数据不变。
- 外部离线ZIP、其他hash续传任务、缓存中用户额外文件保持原样。
- 损坏归档、实际替换故障/回滚及恢复失败均保留材料。
- 真实Windows句柄禁止删除ZIP：安装仍成功、清理结果失败且不循环；关闭句柄后恢复入口重试成功。
- 提交后未清理即退出：恢复入口清理材料而不回滚；启动入口确实调用独立更新器。
- 真实Windows目录联接与非法清理路径被拦截；用户修改过的默认模型备份保留。
- 旧更新器副本可回收，新交接副本和额外用户文件保留。
- 原有签名、大小/哈希、安装锁、原子替换、fsync、事务回滚和Qt响应相关检查通过。

最终冻结产品：

- 离线 `--core-check` 为 `ok=true`；9个相关模块/入口代码对象与最终源码结构相等。
- 使用产品原PYZ的QA变体，仅将内置公钥数据替换为内存生成的测试公钥，真实安装128文件小签名包；文件哈希正确，清理261文件/92,294字节，缓存和事务目录均已删除。
- 实际Qt更新器自动重启探针；重启后真实删除已退出的缓存更新器EXE，个人数据和另一下载任务保留。
- 用产品原PYZ的启动适配入口调用真实bootstrap；发现已提交但未完成的清理任务后，真实复制并启动**生产公钥版本**独立更新器恢复，清理完成后自动重启，已安装新文件未回滚。
- 最终Inno编译成功，11.250秒；ZIP CRC和成员检查通过。QA适配入口未进入交付包。

没有重新下载/安装完整语音包、没有调用付费API或读取生产私钥；没有覆盖日常安装或删除此前移出的20.95 GiB材料。完整包的实际清理耗时未测，不能用小型夹具代替该指标。

证据位于 `work/auto-cleanup-20261025`：`final-key-tests.txt`、`native-cleanup.log`、`native-qa/native-cleanup-result.json`、`core-check.json`、`frozen-code-match.json`、`delivery-result.json`。旧r2/r3工作目录是否保留由用户自行清理，不作为本轮可用证据。

## 交付与使用

主程序修订安装包放在工作暂存目录之外：

`D:\TachiTalk\distribution\TachiTalk-v2.0.0-setup-r4.zip`

- **116,179,318 字节**。
- SHA256：`8d02db72e8753ecb29452b9af1607cceafe062044a1700a3206a852860bc2ed7`。
- 配套 `.zip.sha256`；ZIP包含安装EXE、配套BIN和r4说明。

正常退出现有程序，完整解压ZIP，右键以管理员身份运行安装器，选择原目录覆盖主程序。现有语音无需重新下载；**用r4执行的后续独立语音安装会自动清理**。r3本身不会因源码更新而自动获得此功能。

如需回退主程序，可使用旧修订安装器覆盖主程序，个人数据和语音环境保留。已自动清除的下载材料不作为离线重装副本保留；未来重装语音需要已有外部离线包或重新下载。
