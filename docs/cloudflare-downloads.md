# Cloudflare 主分发渠道

客户端 1.3.4 默认使用 R2 已绑定的 `https://download.jieyiblog.me/`，不依赖 GitHub API 或 `dl.jieyiblog.me` Worker。后者仅支持固定版本附件，不能作为最新版本接口。

## 对象与发布顺序

- `v1.3.0/voice-manifest.json` 和四个原始语音分卷：沿用正式 Ed25519 签名，不修改清单 URL 或压缩包。
- `v1.3.0/TachiTalk-v1.3.0-main.zip`：原正式安装包，SHA256 `d8c45415b858034f8bb31e2df7cd1a003e8f2a6d2c040a69078ed6218e4a7421`。
- `metadata/latest.json`：最新稳定发布的版本、说明、日期和附件名/大小/官方 URL。Cache-Control 为 `no-store`，只用于发现版本，不授权执行补丁。
- `latest/voice-manifest.json`：版本接口失败时的原签名语音清单后备入口。
- 后续发布时，先上传并验证新版本全部附件，再更新 `latest` 签名清单，**最后**上传 `metadata/latest.json`。只改 GitHub Release 不会自动更新 R2 的版本指针。
- 如果新主程序继续沿用旧语音版本，需将旧签名 `voice-manifest.json` 原样上传到新主程序版本目录；分卷仍由清单中的固定旧版本 URL 映射到原 R2 对象，不需要复制大分卷。

`packaging/download_sources.json` 的 `layout: r2` 将官方固定附件 URL 映射为 `<域名>/vX.Y.Z/<文件名>`，版本 API 映射为 `metadata/latest.json`，固定 latest 清单映射为 `latest/<文件名>`。任意外部下载 URL 不会获得此转换能力。

配置版本 4 首次运行时备份旧版本 1/2/3 的配置，加入启用的 Cloudflare 来源并解除旧单源偏好；其他自定义源、禁用选择、待清理任务保留。迁移后用户可以再选择其他来源，不会每次启动重置偏好。新配置启用公共代理作为后备；公共代理开关不控制 Cloudflare，也不等于系统代理设置。

## 更新行为

启动后工作线程静默检查，当前页面继续可用；上次退出停在下载页时本次回到角色控制。安装器明确勾选打开语音面板的 `--install-voice` 入口保留。

只有发现更高版本才弹窗。存在适用的签名增量包时沿用独立更新器及完整验签；缺少适用增量包但存在官方命名完整主程序 ZIP 时，提示用户从 Cloudflare 下载并手动解压安装，不将普通版本元数据当成签名补丁。

安装语音前检查实际选择的渠道。默认 Cloudflare 成功即可以继续，不等待 GitHub；手动检测额外显示 GitHub 连通情况。所有分卷及合并包仍校验 SHA256，安装前仍验证生产签名。

## 验证范围

本轮真实测试：只启用 Cloudflare 后的版本发现、语音生产验签、首分卷两处 1 KiB HTTP206、完整正式主程序 ZIP 下载与 SHA256、版本指针 no-store。不是完整语音下载/安装或所有地区免代理验收。

稳定语音环境为 PyTorch 2.7.1+cu128，包含 sm_120，启动设备默认为 auto；本机为 RTX4060，不冒充 RTX50 实机验收。新用户映射下拉默认自动匹配，已有个人配置不强制清空；源码运行不再读取项目 resources 内的开发者映射 JSON。

Cloudflare 管理脚本与凭据保留原 work 目录，不进入安装包。当前 Worker 管理 Token 请求返回401，本轮无需修改 Worker/DNS；R2 已有对象写权限正常，以上对象已通过该权限上传。


## v1.3.5 下载中断策略

下载开始传输后固定当前来源，并在每个 archive 的下载缓存内记录 source-lock.json。临时连接/读取/服务端429或5xx中断时，在原来源最多尝试3次；续传仍要求同URL、强ETag、匹配的Content-Range和最终SHA。失败后不自动切到其他来源，保留缓存供继续下载；手动切源仍按用户要求清空当前任务缓存（连同来源记录）再从零下载。首次完全不可达、尚无下载进度时才可自动使用后备。元数据/签名清单的多源发现规则保留，不能把源锁策略用来跳过验签。

安装按钮下方的约5分钟提示是首次准备的预计时长；阶段文本区分验签、安装空间/现有文件扫描、缓存检查、实际下载。准备时显示不确定进度与真实已用时间，不使用假倒计时或固定延时；有真实下载数据后才展示百分比。
