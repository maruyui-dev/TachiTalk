## 最终安装流程与实际减少的工作

正常安装显示：**准备安装 → 安装文件 → 清理安装材料 → 重新启动主程序**。等待主程序退出、故障恢复仍按实际发生显示；卸载仍保留原有校验步骤。旧更新器不会在执行中热换成r5。

- 解压读取时同时计算每个文件大小和 SHA256，完整通过后才能安装该文件；取消解压后独立重读全部文件的校验阶段，保留归档哈希及清单签名。
- 新文件只写一次到本卷事务目录，flush/fsync 后原子移入目标；取消 stage 到目标的第二次整文件复制。成功后 stage 不再保存完整资源副本。
- 有旧文件时，普通供应商文件优先用硬链接保留旧文件实体，再对新文件使用原子替换；文件系统或权限不支持时，自动使用同步复制备份。备份副本的哈希仍用于恢复校验。
- 默认权重和参考音频仍保留独立复制备份；用户修改过且与原托管记录不一致的备份不会作为垃圾清理。用户自有角色、模型、源音频、设置、记忆与未托管文件不扫描删除。
- 完整恢复计划在第一个实际目标变化前一次持久写入。文件损坏、写入故障或进程中断仍能够按原 journal 恢复，失败时保留修复材料。
- 提交成功后继续使用r4的精确清理：本任务下载分卷、合并ZIP、暂存和普通备份；保留其他任务、缓存中的额外用户文件及外部离线ZIP。随后自动启动主程序。清理失败单独显示，不把安装成功伪装成失败，也不制造重启循环。
- 实际完成字节和文件数量更新真实进度时间；心跳不冒充工作推进。未知总量的准备步骤显示“处理中”。进度窗口保持响应、可最小化，不提供强杀取消按钮。

普通文件硬链接只在安装恢复期间存在，提交后按任务清理；不会把新安装内容写入旧备份实体。
